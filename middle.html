Middle–High School Curriculum

A fast-paced 8-week program for students with prior computer comfort. Extends into functions, radio networking, and text-based code (JavaScript/Python). Each session runs 60–75 minutes.

Weekly Session Format (60–75 Minutes)

5 mins Recap of last week's vocabulary and quick questions
5–10 mins Introduce the day's concept and its real-world use
35–45 mins Hands-on building time following the step-by-step guide
10–15 mins Test, extend, and discuss

Learning Goals

  • Get oriented to the micro:bit hardware and the MakeCode editor quickly.
  • Complete two starter projects: a scrolling name badge and an animated beating heart.
  • Begin building a shared vocabulary list to use for the rest of the program.

Materials Needed

  • One computer per student (or pair)
  • One micro:bit board per student (or pair)
  • One USB cable per micro:bit

Step-by-Step Lesson

  1. Give a brief tour of the micro:bit board: the 25 LEDs, Buttons A and B, the accelerometer (motion sensor), the light and temperature sensors, the radio antenna, the USB port, and the battery connector.
  2. Have students go to makecode.microbit.org and start a new project called "Name Badge."
  3. Using the "Basic" category, build a scrolling name badge: place "show string" with your name inside a "forever" block, under "on start."
  4. Download and test the badge on the micro:bit.
  5. Start a second new project called "Beating Heart." Use two "show leds" heart shapes of different sizes with short pauses between them, all placed inside a "forever" loop, to make an animated heartbeat.
  6. Explain the technical definition of a loop as they build it: a loop is a block of instructions that a program repeats, either a set number of times or forever, without the instructions needing to be written out again.
  7. Download and test the second project.

Optional Challenge (for students who finish early)

Have faster-finishing students try a three-frame heartbeat animation, or design their own simple animation from scratch.

Wrap-Up

Start a running vocabulary list on the board or a shared document: algorithm, loop, variable, condition, sensor, input, output. Add to this list every week.

Learning Goals

  • Use button inputs to trigger different outputs.
  • Create and update a variable using the accelerometer.
  • Discuss real-world uses of motion sensors.

Materials Needed

  • One computer per student (or pair)
  • One micro:bit board per student (or pair)
  • One USB cable per micro:bit

Step-by-Step Lesson

  1. Start a new project called "Emotion Badge." Use "on button A pressed" and "on button B pressed" with two different "show icon" blocks to display two different expressions.
  2. Download and test on the micro:bit.
  3. Start a new project called "Step Counter." Create a variable called "steps," set it to 0 in "on start," and use "on shake" to add 1 to it and then display it.
  4. Discuss why the display block must come after the block that changes the variable, not before, or the count shown will always be out of date by one.
  5. Download and test by shaking the micro:bit.
  6. Extension: add an "on button B pressed" block that sets "steps" back to 0, so the counter can be reset.

Optional Challenge (for students who finish early)

Challenge students to add a second variable that tracks the highest step count ever reached in a session, even after a reset.

Wrap-Up

Discuss where accelerometers are used in everyday devices: phones (to rotate the screen), fitness trackers, cars (airbag sensors), and game controllers.

Learning Goals

  • Use the light sensor and conditional logic to build an automatic nightlight.
  • Learn what a function is and why programmers use them to organize code.

Materials Needed

  • One computer per student (or pair)
  • One micro:bit board per student (or pair)
  • One USB cable per micro:bit

Step-by-Step Lesson

  1. Start a new project called "Nightlight." Using "light level," a comparison block, and an "if / then / else" block inside a "forever" loop, build the same logic used in the elementary plan's Week 6, but move through the steps more quickly since students already understand "if/then" from Week 2's step counter reset.
  2. Test and adjust the light-level number for the room, and download the finished version.
  3. Open the "Functions" category (or "Advanced" then "Functions" if it is hidden) and click "Make a Function." Name it something like "turnLightOn."
  4. Move the blocks from inside the "then" section of the if/then/else into this new function instead, and replace them with a single block that calls the function.
  5. Explain that a function is a named, reusable bundle of instructions — instead of writing the same blocks over and over, you can just call the function by name wherever you need it.
  6. Download and retest to confirm the program still works exactly the same after being reorganized into a function.

Optional Challenge (for students who finish early)

Add a third light condition (a dim, in-between reading) with its own function, using an "else if."

Wrap-Up

Discuss why keeping code organized into functions matters more as a program gets longer and more complex.

Learning Goals

  • Use randomness to build a game.
  • Extend the basic random-choice game into a program with a scorekeeping opponent, using nested logic.

Materials Needed

  • One computer per student (or pair)
  • One micro:bit board per student (or pair)
  • One USB cable per micro:bit

Step-by-Step Lesson

  1. Build the basic Rock, Paper, Scissors program: a variable "choice," set using "pick random 0 to 2" on "on shake," and an if/else if/else block showing rock, paper, or scissors icons.
  2. Download and test the basic version.
  3. Add two new variables: "wins" and "losses," both starting at 0.
  4. Add a second variable, "computerChoice," also set using "pick random 0 to 2" each time the micro:bit is shaken, representing a hidden opponent.
  5. Using nested "if / then" blocks, compare "choice" and "computerChoice" to decide the outcome: rock beats scissors, scissors beats paper, and paper beats rock. Add 1 to "wins" or "losses" depending on the result, and briefly show a check mark or X to indicate who won that round.
  6. Download and test several rounds, checking that the win/loss variables update correctly.

Optional Challenge (for students who finish early)

Add a "show number wins" and "show number losses" option triggered by pressing Button A or B, so players can check the score at any time.

Wrap-Up

Discuss how this project is much closer to a real single-player video game: a hidden computer opponent that also makes a random choice, and rules that decide a winner.

Learning Goals

  • Understand how micro:bits can send and receive short-range radio messages.
  • Program two micro:bits to communicate with each other.

Materials Needed

  • One computer per pair of students
  • Two micro:bit boards per pair of students (required for radio communication)
  • Two USB cables

Step-by-Step Lesson

  1. Explain that micro:bits have a small radio antenna built in, allowing them to send and receive short messages with other nearby micro:bits, similar to a walkie-talkie.
  2. Start a new project called "Radio Chat."
  3. Open the "Radio" category (it may be under "Advanced") and drag "radio set group" into "on start," setting it to a shared number, such as 1, so only paired micro:bits will hear each other.
  4. For the first micro:bit in a pair: under "on button A pressed," add a "radio send number" block set to 1, and also show a checkmark icon so the sender knows a message went out.
  5. For the second micro:bit in the pair: use the "on radio received receivedNumber" block, and inside it, place a "show icon" checkmark block.
  6. Download the first program to one micro:bit and the second program to the other micro:bit in the pair.
  7. Test it: press Button A on the first micro:bit and watch the second micro:bit display a checkmark.
  8. Extension: change the blocks to use "radio send string" and "on radio received receivedString" to send a short word or message instead of just a number.

Optional Challenge (for students who finish early)

Have pairs write a very simple back-and-forth "conversation" where each button press sends a different message and triggers a different icon on the other board.

Wrap-Up

Discuss other everyday devices that use short-range radio signals, such as garage door openers, car key fobs, and wireless doorbells.

Learning Goals

  • See that block code and text-based code (JavaScript or Python) do exactly the same thing.
  • Read and make a small edit directly in text-based code.

Materials Needed

  • One computer per student (or pair)
  • One micro:bit board per student (or pair, optional this week)

Step-by-Step Lesson

  1. Open the Rock, Paper, Scissors project (or any earlier project) in MakeCode.
  2. Find the toggle near the top of the editor that switches between "Blocks" and "JavaScript" (some versions also offer "Python"). Click it to see the same program written as text.
  3. Read through the generated text code as a group, line by line, matching each line back to the block it came from.
  4. Explain that this side-by-side view is exactly why a video is not needed here — the connection between blocks and text is visible directly in the editor.
  5. Have each student make one small, safe edit directly in the text view, such as changing an icon's name or a number, then switch back to "Blocks" to confirm the change shows up there too.
  6. Discuss that professional software is almost always written as text code, and that the blocks are a stepping-stone toward writing text code with the same ideas: variables, loops, conditions, and functions.

Optional Challenge (for students who finish early)

Let students try switching an entire simple project (like the Name Badge) back and forth between Blocks and text a few times to get comfortable with the toggle.

Wrap-Up

Quick vocabulary check: ask students to define "syntax" (the exact spelling and punctuation rules of a programming language), "string" (text data), and "integer" (a whole number), in their own words.

Learning Goals

  • Design an original micro:bit project that combines at least two inputs and one loop or condition.
  • Practice planning a program on paper before building it.

Materials Needed

  • One computer per student (or pair)
  • One micro:bit board per student (or pair)
  • Paper and pencil for planning

Step-by-Step Lesson

  1. As a group, brainstorm possible final project ideas, for example: a dice roller, a digital compass, a reaction-time game, a thermometer display, a quiz-buzzer game, or a simple alarm.
  2. Have each student (or pair) choose one idea and write a short plan on paper: what inputs will be used (buttons, shake, light, sound, temperature), what outputs will happen (icons, numbers, sounds), and what loop or condition the program will need.
  3. Begin building the project in MakeCode, checking in with the written plan along the way.
  4. Encourage testing early and often: download a partial, simple version of the project to the micro:bit before adding more features, to make sure the basics work first.
  5. Circulate to help students debug problems, such as blocks in the wrong order or a comparison that never becomes true.

Wrap-Up

Have students pair up to briefly explain their plan to a partner and get one piece of feedback before continuing next week.

Learning Goals

  • Complete and thoroughly test the final project.
  • Practice explaining a technical project clearly to an audience.

Materials Needed

  • One computer per student (or pair)
  • One micro:bit board per student (or pair)

Step-by-Step Lesson

  1. Give students time to finish building and downloading their final projects.
  2. Guide the group through common debugging checks: is the order of the blocks correct, do the variable names match everywhere they're used, and did the download fully finish (the light on the back blinked, then stopped)?
  3. Have each student (or pair) prepare a short, 1–2 minute explanation covering: what the project does, which inputs, outputs, and logic it uses, and one thing that was difficult to figure out and how it was solved.
  4. Hold a "demo day": have each student or pair present their finished micro:bit project to the rest of the group.
  5. Close with a group discussion: what would you like to try next with a micro:bit? Options might include more sensors, a bigger radio-based game between many micro:bits, or writing an entire project directly in Python.

Wrap-Up

Ask each student to name one concept from the past 8 weeks (loop, variable, condition, function, radio, sensor) that they now feel confident explaining to someone else.
